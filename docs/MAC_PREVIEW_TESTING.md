# Yita macOS Apple Silicon 试用版

此包用于同学协助测试，不是已完成真机验收的正式版本。仅面向 Apple Silicon（M1/M2/M3/M4 等 M 系列芯片），不支持 Intel Mac。包元数据最低 macOS 12.0；实际兼容性以测试记录为准。

应用自带 .NET 运行时，无需安装 .NET、SDK、Xcode 或 Rosetta。需要联网和自己的 DeepSeek API Key。本轮没有发布公共 GitHub Release，也没有配置自动更新。

## 安装与首次启动

1. 打开 `Yita-0.9.0-macos-preview.*-osx-arm64.dmg`，将 `Yita.app` 拖到 `Applications`。不要直接在 DMG 中长期运行，开机启动应指向已安装应用。
2. 弹出 DMG，再从“应用程序”打开 Yita。ZIP 是备用格式：在 Mac 上解压，将其中的 `Yita.app` 移到“应用程序”。两种包内容相同，不要同时运行多份。
3. 本试用包仅使用 ad-hoc 签名，没有 Apple Developer ID 签名和公证。首次启动如被系统阻止，在确认文件来自维护者后，打开“系统设置 → 隐私与安全性”，使用对应的“仍要打开”并完成系统确认。较旧系统也可能提供右键“打开”。不需要关闭系统安全功能或执行清除 quarantine 的命令。
4. 设置页配置 DeepSeek 模型及 API Key，测试连接，再保存设置。Key 保存在当前用户的 macOS Keychain；若系统请求钥匙串访问，请按照实际提示处理。
5. 在“常规”中申请/检查辅助功能和输入监控权限，通过应用入口打开系统设置。系统可能显示 `Yita` 或 `Yita Native Helper`，以实际被请求的条目及应用显示的权限状态为准。
6. 若系统要求手动添加原生组件，可以在权限列表的“+”文件选择器中按 `Cmd+Shift+G`，定位 `/Applications/Yita.app/Contents/Helpers/Yita.Native.Mac.Helper.app`。授权后退出并重新打开 Yita，检查权限和输入捕获状态，再启用自动划词。

请先完成 Gatekeeper 启动确认，再检查取词权限。辅助功能/输入监控和 API 连接是不同环节，测试连接成功不代表取词权限已经授予。

## 手动验收清单

| 测试 | 预期 |
| --- | --- |
| 首次打开、设置连接并保存 | 能显示设置；真实翻译请求成功；没有启动即退出 |
| Safari/Chrome 普通网页拖选英文 | 选区附近出现浮窗并流式显示译文；连续选择不会展示旧结果 |
| TextEdit、VS Code/Markdown 的可复制文本 | 可通过 AX 或安全 Cmd+C 回退取词；失败给出可读状态 |
| Preview/其他 PDF 阅读器的可复制 PDF | 拖选可尝试翻译；记录具体软件及文件类型；扫描图无 OCR 支持 |
| 正常 `Cmd+C` / `Cmd+V` | 正常复制粘贴不受破坏；自动复制后原剪贴板可恢复 |
| 手动复制后 `Cmd+Shift+T`，或菜单“翻译剪贴板” | 能翻译现有剪贴板；用于区分取词问题和模型问题 |
| 暂停自动划词、恢复/修复输入捕获 | 暂停有效，手动入口可用，恢复后可继续测试 |
| 浮窗原文/译文、固定、关闭、缩放和拖动 | 内容可读；相对于新选区保留拖动偏移；缩放光标正确 |
| 解释、问答、术语/修正、AI 记录 | 功能能打开和保存；重启后记录/修正按现有设置保留 |
| 语言、外观、减少动画 | 设置、菜单栏和浮窗语言同步；平台字体及动画偏好生效 |
| 关闭设置、二次启动、退出 | 关闭设置后菜单栏可再次打开；二次启动唤醒已有实例；退出释放 helper |
| Keychain、开机启动 | 重启后配置可读取；启用登录项后下次 GUI 登录后台启动；关闭登录项有效 |
| 睡眠/唤醒、全屏/Spaces、Retina/多屏 | 能恢复输入；浮窗位置和焦点合理；记录异常系统/屏幕配置 |
| 连续划词和后台使用 | 先做短时连续选择，再测试较长时间运行；不崩溃、不挂起 |

“任何地方划词”仍受系统和目标软件限制：密码框、受保护内容、禁止复制和不暴露选区的控件不保证读取。无需为了测试授予全磁盘访问权限。

## 反馈格式

- 包文件名、Mac 芯片、macOS 版本、目标应用及版本。
- 出问题的步骤；自动划词、手动复制快捷键、菜单剪贴板翻译各自是否成功。
- 设置页权限/输入捕获状态，以及菜单栏“复制性能诊断”的文本。诊断默认不包含选中文字和 API Key。
- 若崩溃，提供 Console/“控制台”中的 Yita 崩溃报告，或 `~/Library/Logs/DiagnosticReports/` 对应报告。发送前检查报告中可能出现的个人路径。
- 请勿发送 API Key、Keychain 内容或包含敏感正文的配置/截图。

## 构建与校验说明

维护者可在 Apple Silicon Mac 上执行 `bash scripts/Build-Mac-Preview.sh <输出目录> <数字构建号>`。GitHub 工作流 `Apple Silicon preview package` 生成同样的包，Actions artifact 默认保存 30 天；维护者下载到本地后不受该期限影响。

输出包括 DMG、备用 ZIP、`SHA256SUMS.txt`、构建 JSON 和本文。JSON 记录提交、RID、运行时与签名状态。SHA256 用于校验文件传输完整性，正式来源身份仍依赖可信下载源及代码签名。

随包许可证在 `Yita.app/Contents/Resources/Licenses/`。构建会检查 ARM64 原生二进制、签名、运行时、主/helper 元数据与通信，并挂载 DMG、解压 ZIP 后再次检查。检查不请求真实 Accessibility/Input Monitoring 权限、不读取其他应用选区、Keychain 或真实 API；测试通过不替代上面的真机清单。

当前预览使用 .NET 8；正式长期发布前仍按路线图升级受支持的 LTS，补齐 Developer ID、公证、升级与真机验收。测试版更新由维护者发送新包，退出旧版后替换“应用程序”中的 Yita，不主动删除用户设置或钥匙串。
